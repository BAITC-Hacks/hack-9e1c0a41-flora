## 2. Что мы знаем о механике (из кода среды)

- Эффект на абонента = `arpu_change_pct × min(conversion × множитель_канала, 1) × predicted_arpu`.
  Зависит только от связки **(текущий тариф, ARPU-сегмент) → целевой тариф** и от канала.
- В публичной механике внутри ячейки (текущий тариф × ARPU-сегмент) одинаков относительный эффект;
  абсолютный прирост различается из-за `predicted_arpu`. Пилот измеряет ratio ячейки для выбранного канала.
- Шум пилота: нормальный, среднее 0, стандартное отклонение `0.804/sqrt(n_actual)`.
  При n=200 sd≈0.057, при n=30 — 0.147. Брать фактическое `res["n_customers"]`, не запрошенный размер.
- Каналы: push 0 у.е. ×0.50 · sms 4 у.е. ×0.65 · digital_ads 22 у.е. ×0.85 · call 160 у.е. ×1.20.
  SMS-пилот на 200 человек стоит 800 у.е.; его абсолютный шум такой же, как у push того же размера.
  У SMS сильнее сигнал, но push бесплатен по деньгам. Оба расходуют контакты и могут снизить ARPU.
- Наблюдаемый ratio уже содержит конверсию и множитель канала: повторно умножать на них нельзя.
  Перенос оценки push ↔ SMS ↔ digital_ads пропорционален множителям при данной механике.
  Для call конверсия ограничена единицей: перенос `sms_ratio * 1.20/0.65` может завысить эффект,
  поэтому call исключаем из v1, а в v2 используем только с обоснованной оценкой/отдельным пилотом.
- Дефицитны **контакты** (15 000 на 23 441 абонента) и **слоты кампаний** (10). Ячейки с одним целевым тарифом
  и каналом объединяем через `filter_current_tariff = "a;b;c"` только при совпадении остальных фильтров.
  Объединение разных ARPU-сегментов может захватить непроверенные комбинации и ухудшить результат.
- Кампания >5 000 абонентов обрезается по `ID_NUMBER`, а не по ценности, поэтому держим сегменты ≤5 000.
- Абонент засчитывается один раз, по лучшей кампании. Повторный контакт не суммирует эффекты,
  но может заменить меньший эффект большим. Цена и контакт списываются каждый раз, включая пилоты.
  В v1 финальные сегменты делаем непересекающимися, пересечение с пилотами учитываем отдельно.
- Судейская модель эффектов **заметно отличается** от истории. История — только априорная оценка.
  Настраиваем логику, а не константы под мок.
- История смен содержит уже перешедших клиентов: доля таких строк не является вероятностью отклика
  на предложение. Историю используем для ранжирования гипотез, с неопределённостью переноса на новую аудиторию.
- Бейзлайн (шаблон организаторов, мок, seed 42): **−1 035 279**. Повторно подтверждён запуском
  `local_eval.py` 23.09.2026 при ревью плана. Это один seed, не средний результат шаблона.
  Бездействие: чистый прирост **0**, общая базовая выручка **150 641 084** (округлённо).
  Бездействие используем для сравнения, но оно не закрывает must-have про пилоты и 1–10 кампаний.

## 3. Архитектура агента (владелец — Claude)

```
история (data/change_tariff.csv) ─► априорная оценка эффекта по ячейкам, с широкой неопределённостью
                                       │
профиль аудитории ─► ценность ячейки (размер × средний predicted_arpu)
                                       │
            ┌──────────── цикл разведки (до 20 пилотов) ────────────┐
            │ выбор пилота: верхняя граница × ценность ячейки (UCB)  │
            │ env.run_pilot(sms, n адаптивно) → байесовское обновление│
            │ учёт цены, риска падения ARPU, контактов и остатка времени │
            └─────────────────────────────────────────────────────────┘
                                       │
отбор: нижняя оценка чистой выгоды > 0 ─► push/SMS в v1
─► 1–10 непустых кампаний с явным учётом всех лимитов и резервным сценарием
                                       │
agent.trace (журнал решений) ─► панель + опциональное объяснение после расчёта
```

Решения воспроизводимы при одинаковых данных, seed среды и настройках; при других пилотах меняются.
Формула для непересекающегося финального сегмента: `net_lower = ratio_lower * sum(predicted_arpu)
- n_customers * cost_per_contact`. Положительного ratio недостаточно для окупаемости платного контакта.
Итог проверяем официальным скорингом с пилотами и дедупликацией, а не суммой оценок таблицы плана.

Первый этап: небольшое множество гипотез, фиксированный размер пилота в пределах 10–200,
обновление оценки по результатам, консервативный отбор, push/SMS, корректный CSV. Адаптивные размеры,
UCB и объединение кампаний добавляем после рабочего полного прогона. Нижняя граница модели —
эвристическая оценка риска, а не гарантия прибыли; строгий порог может обнулить план.

Если ни одна гипотеза не проходит порог: при наличии ресурсов перепроверить лучшую неопределённую
гипотезу. Если положительных доказательств всё ещё нет, вернуть одну непустую допустимую кампанию
с минимальным оценённым ущербом и явно отметить неопределённость. Резервировать для этого контакты,
не подменять её пустым сегментом; прибыль такой кампании не гарантируется.
Перед возвратом независимо проверить число кампаний, тарифы, фильтры, размеры сегментов,
остаток бюджета и контактов после пилотов. Автообрезка среды не заменяет планирование лимитов.

Шаблонное объяснение доступно без API. Опциональное LLM-объяснение вызывается панелью после расчёта,
с ограничением времени и запасным текстом. Оно не должно задерживать `act(env)`, оценку или генерацию CSV.
Агент принимает решения статистическим алгоритмом; не заявляем, что ими управляет LLM.

## 7. Что считаем готовым результатом

- Проект запускается по README из чистого клона с явно указанной версией Python и зависимостями.
  При ревью команда `python` не найдена в PATH текущей оболочки; бейзлайн запущен доступным локальным
  интерпретатором. Это нужно решить и описать для установки, не привязывая README к личному пути участника.
- На каждом проверочном seed агент использует пилоты и возвращает 1–10 непустых допустимых кампаний.
  Нет падений, отброшенных кампаний, превышений/неожиданной обрезки; время прогона измерено.
- `make_submission.py` дважды в отдельных процессах при неизменных настройках формирует одинаковый
  `submission.csv` на seed 42. Проверить колонки, 1–10 строк; положить CSV в итоговый репозиторий.
- Для v1: 0–9 и 42. Для окончательной проверки: заранее отложенные seed 10–19 после фиксации стратегии,
  без подбора параметров под них. Сравнить нашу версию и неизменённый шаблон на одинаковых seed.
  Сохранить минимум, медиану, число положительных прогонов, затраты и время. Цель — положительный
  net и преимущество над шаблоном; улучшение с -1 млн до -0.5 млн всё ещё означает убыток.
- Разные seed меняют шум и выборки, но не истинные эффекты мок-модели. Отдельный стресс-стенд проверяет
  собственные синтетические сценарии: слабый сигнал, отрицательные эффекты, расхождение с историей.
  При всех отрицательных эффектах прибыль может быть невозможна: проверяем соблюдение условий и
  ограничение ущерба, не требуем искусственного плюса. Стенд не меняет файлы организаторов и не
  передаёт скрытую модель агенту; в `agent.py` нет импорта стенда или доступа к internals среды.
- Панель показывает реальный одиночный запуск, правильные метрики и понятную причину выбора кампаний.
  Тестовые данные интерфейса явно помечены и не участвуют в демонстрации результата.
- Никаких утверждений о гарантированной прибыли, судейском балле или превосходстве в продакшене:
  данные синтетические, скрытые эффекты неизвестны, число испытанных гипотез ограничено 20 пилотами.
